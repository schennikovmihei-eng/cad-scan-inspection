# Стенд сравнения скана с CAD

Одна команда последовательно запускает уже проверенные на паре `shoe` вычислительные этапы. Стенд сохраняет матрицы совмещения, расстояния до треугольной поверхности CAD, сравнение SOR/Pointfilter, время этапов и сведения об окружениях.

## Запуск на настроенном ноутбуке

Распакуйте папку `cad_scan_stand` внутрь `C:\Users\mihei\Desktop\vkr`, рядом с `shoe.stl`, `shoe_clean.ply`, `.venv`, `.venv-ai` и `Pointfilter`. Вложенность должна быть такой: `vkr/cad_scan_stand/run_stand.py`.

В PowerShell выполните одну команду:

```powershell
& "C:\Users\mihei\Desktop\vkr\.venv\Scripts\python.exe" "C:\Users\mihei\Desktop\vkr\cad_scan_stand\run_stand.py"
```

Из уже открытого терминала Ubuntu можно вызвать тот же Windows Python:

```bash
/mnt/c/Users/mihei/Desktop/vkr/.venv/Scripts/python.exe C:/Users/mihei/Desktop/vkr/cad_scan_stand/run_stand.py
```

Также можно открыть `start.cmd`. Активация окружений вручную не нужна: программа вызывает их интерпретаторы явно, а нейросетевую регистрацию запускает через WSL и `conda run`.

После строки `COMPLETED:` откройте указанную папку. В ней находятся:

- `report.md` — краткий отчёт с таблицами;
- `filter_comparison.csv` — сравнение исходного облака, девяти вариантов SOR и Pointfilter;
- `summary.json` — полные статистики совмещения и фильтрации;
- `config.json`, `run.json` — настройки, статус и время каждого этапа;
- `logs/` — вывод программ, версии библиотек и `pip freeze` каждого окружения;
- `data/` — копии входных данных и все промежуточные результаты этого прогона.

Программа создаёт новую папку `vkr/stand_runs/run_<дата_UTC>`. Предыдущие скрипты, данные и результаты не перезаписываются. Окна визуализации не блокируют полный прогон.

## Рисунки для отчёта

После завершённого прогона отдельный экспорт читает сохранённые массивы и статистики. Повторная регистрация, ICP и нейросетевая фильтрация не выполняются.

В текущем терминале Ubuntu:

```bash
/mnt/c/Users/mihei/Desktop/vkr/.venv/Scripts/python.exe C:/Users/mihei/Desktop/vkr/cad_scan_stand/export_figures.py
```

Из PowerShell:

```powershell
& "C:\Users\mihei\Desktop\vkr\.venv\Scripts\python.exe" "C:\Users\mihei\Desktop\vkr\cad_scan_stand\export_figures.py"
```

Можно также открыть `start_figures.cmd`. Экспорт использует NumPy, Matplotlib и Open3D из существующего Windows `.venv`, не требует графического окна или загрузки нейросетей.

По умолчанию выбирается последний завершённый прогон. Внутри него создаётся новая папка `figures_<дата_UTC>` с четырьмя рисунками, каждый в **PNG 300 dpi и PDF**, с белым фоном:

| Имя | Содержание |
|---|---|
| `01_registration` | Полный скан и поверхность CAD: ручное + ICP как контроль, выбранный конвейер — рядом в том же ракурсе |
| `02_deviation_maps` | Карты расстояний до CAD до фильтрации, после SOR 20/2 и после Pointfilter; общая цветовая шкала |
| `03_filter_metrics` | Процентные изменения среднего, P95 и стандартного отклонения для девяти SOR и Pointfilter; рядом доля удалённых точек |
| `04_distance_distribution` | Эмпирические распределения расстояний до CAD до/после фильтрации |

`captions.txt` содержит подписи к рисункам; `figures.json` — источник данных, хеши, ракурс и параметры отображения. PDF удобен для Overleaf, PNG — для Word. У PDF подписи остаются векторными, а изображения геометрии растрируются с выбранным dpi.

Синий на карте означает меньшее расстояние, красный — большее. Единицы исходной CAD-модели пока не переведены в миллиметры. SOR показан только по оставшимся точкам; цвет сам по себе не доказывает наличие шума или дефекта.

Ракурс общий для всех облаков, на основе одного PCA-базиса CAD. Сетка упрощается **только для отрисовки** до 30 000 треугольников; расстояния берутся из результатов расчёта по исходной сетке. Для отрисовки всех треугольников добавьте `--mesh-faces 0`.

По умолчанию камера повёрнута вокруг направления взгляда на 180° (`--roll=180`), чтобы показанный тапок располагался подошвой вниз. Этот поворот применяется одинаково ко всем 3D-панелям; подписи и цветовая шкала остаются прямыми. Координаты, совмещение и расстояния не меняются. `--roll=0` возвращает первоначальное отображение.

Чтобы изменить ракурс, например показать нижнюю сторону, добавьте `--elev=-20 --azim=-65`. Параметр `--run` позволяет указать конкретную папку прогона. `--metrics-only` строит только график показателей по `summary.json`, без геометрических файлов. Пример такого графика на уже полученных реальных результатах включён в `example_results/figures_*`.

Рендеринг всех четырёх рисунков и общая цветовая шкала проверены на тестовой геометрии. Карты реального скана строятся на ноутбуке из сохранённых массивов; сами эти массивы в архив не включены. Вычислительные программы полного конвейера при добавлении экспорта не изменялись.

## Что именно выполняется

1. Проверка трёх существующих окружений и входных файлов.
2. Согласование масштаба: из сохранённого `aligment.npz` берётся только положительный равномерный коэффициент. Ручные поворот и перенос не передаются нейросети.
3. Нейросетевая регистрация GeoTransformer с нативной конфигурацией и весами ModelNet: 717 точек на вход каждого облака, `eval()` и `inference_mode()`, без передачи истинного преобразования.
4. Уточнение ICP без дополнительного масштабирования.
5. Проверка 24 геометрических гипотез ориентации в базисе PCA эталона с уточнением ICP. Кандидат выбирается по расстояниям до фиксированной выборки CAD; ручная поза не используется при выборе.
6. Применение выбранного преобразования ко всем точкам скана. Расчёт расстояний до треугольников исходного STL и сравнение с сохранённым ручным совмещением + ICP.
7. Независимые ветви SOR и Pointfilter, каждая начинает с одного и того же совмещённого облака. Совмещение после фильтрации не пересчитывается.
8. Экспорт общей таблицы и отчёта. Среднее, медиана, стандартное отклонение, P95 и максимум доступны в CSV/JSON; изменения указаны в процентах относительно облака до фильтрации.

Это гибридный метод **GeoTransformer + ICP + геометрический поиск ориентации**. Результат всего конвейера нельзя приписывать одной нейросети. В этой демонстрационной конфигурации ICP выполняется всегда: на имеющейся паре он оказался необходим.

## Настройки

Все параметры запуска находятся в `config.json`. Относительные пути к файлам и окружениям разрешаются относительно `project_dir`; сам `project_dir` — относительно файла настроек. По умолчанию проект расположен на уровень выше папки стенда.

В `wsl` указаны Ubuntu, пользователь `mihei`, существующий Miniforge и репозиторий GeoTransformer. Проверяется уже использованный коммит `e7a135af4c318ff3b8d7f6c963df094d7e4ea540`. Пути Windows преобразуются для стандартного монтирования дисков WSL `/mnt/c/...`.

Для повторения текущего эксперимента включён `preparation.mode = "reuse_fixed_sample"`: программа копирует имеющиеся `registration_input/src.npy`, `ref.npy`, `preparation.npz`, проверяет их соответствие исходному скану, масштабу и STL. Это сохраняет одну и ту же исходную выборку из 5000 точек при сравнении методов.

Для новой калиброванной пары можно выбрать `"resample"`: программа построит новую выборку с заданным `seed`, `sample_points` и `network_diagonal`. До этого надо указать правильные `mesh`, `scan` и **относящийся к этой паре** `manual_calibration`. Автоматической оценки масштаба по частичному скану в этой версии нет. Файлы STL/PLY копируются в рабочую папку под фиксированными внутренними именами.

Девять комбинаций SOR заданы в массиве `sor`. Pointfilter использует параметры уже проведённого эксперимента: `patch_radius=0.05`, `points_per_patch=500`, веса `Pointfilter/Summary/pre_train_model/model_full_ae.pth`. Эти параметры и хеш весов записываются в результаты.

Можно указать отдельный файл настроек:

```powershell
& "C:\Users\mihei\Desktop\vkr\.venv\Scripts\python.exe" "C:\Users\mihei\Desktop\vkr\cad_scan_stand\run_stand.py" --config "C:\Users\mihei\Desktop\vkr\cad_scan_stand\config.json"
```

Если этап завершился ошибкой, в папке прогона останутся его журнал и `run.json` со статусом `failed`. После исправления причины обычная команда создаёт новый прогон. Параметр `--resume` предназначен для повторной сборки отчёта из завершённых этапов: он проверяет конфигурацию и хеши результатов. Частично выполненный этап автоматически не продолжается.

## Используемые окружения

| Этап | Окружение | Проверенные ранее версии |
|---|---|---|
| Чтение STL/PLY, поверхность CAD, SOR, отчёт | Windows `.venv` | Точная версия Open3D/NumPy считывается при запуске |
| GeoTransformer, ICP, гипотезы ориентации | Ubuntu / Conda `geotransformer` | Python 3.8.20, Torch 1.10.1+cu111, NumPy 1.23.5, Open3D 0.11.2 |
| Pointfilter | Windows `.venv-ai` | Python 3.13.14, Torch 2.10.0+cu128 |

Этот архив предназначен для уже настроенных окружений. Он не устанавливает зависимости, не скачивает модели и не объединяет несовместимые версии библиотек. Модели, сторонние репозитории и геометрические данные в архив не включены.

В используемом GeoTransformer ранее собран CPU-модуль расширения: в `setup.py` применён `CppExtension`, а из `geotransformer/extensions/common/torch_helper.h` удалён лишний `#include <ATen/cuda/CUDAContext.h>`. Выполнение самой сети по-прежнему использует CUDA. Проверка запуска импортирует скомпилированный модуль; автоматического изменения этих исходников здесь нет. Для инференса создаётся отдельный `model_for_stand.py`, исходный `model.py` сохраняется.

## Как трактовать результаты

Расстояния вычисляются от точек к **ближайшей точке треугольной поверхности**, а не к ближайшей вершине. Используются расстояния без знака. Физическая единица исходной CAD-модели пока не подтверждена.

SOR удаляет точки. Его среднее и P95 рассчитаны только по оставшимся точкам, поэтому их надо рассматривать вместе с долей удалённых. Pointfilter сохраняет число точек, но изменяет координаты; величины смещений также сохраняются.

Уменьшение расстояния до CAD само по себе не доказывает удаление шума: могут измениться реальные особенности поверхности. Сохранённые ручное совмещение и ICP служат контрольным решением, а не истинной позой. Полный скан может покрывать только часть изделия; односторонняя метрика не оценивает полноту покрытия CAD.

Повторяемость обеспечивают фиксированные входные выборки, настройки, seed, версии, хеши и сохранённые преобразования. Побитовое совпадение результатов CUDA на разных версиях и устройствах не гарантируется.

## Проверка этой сборки

Полный единый запуск подтверждён на ноутбуке пользователя 30 октября 2026 года: все шесть вычислительных этапов завершились со статусом `completed`. Использованы 14 304 точки скана и 165 591 треугольник CAD; Pointfilter не пропустил ни одной точки. Результаты совмещения и фильтрации совпали с предыдущим отдельным прогоном в показанных числах. Это подтверждение работы на одной имеющейся паре, а не оценка обобщения на другие изделия. Сводка приведена в `RESULTS.md` и `observed_results.json`, полученные от пользователя исходные журналы — в `example_results/run.json` и `example_results/summary.json`.

В среде подготовки архива проверены передача путей Windows/WSL, последовательность этапов, изоляция прогонов, восстановление настроек масштаба, запрет смешивания входов и результатов, формирование отчёта и обработка отказа дочерней программы. В этих проверках внешние вычислительные процессы заменены контролируемыми тестовыми результатами. Затем пользователь выполнил реальный полный запуск с CUDA и WSL. Приложенные JSON согласованы по статусам, числу точек, хешам входа Pointfilter и совмещённого облака, хешу STL и ссылке на отчёт совмещения. Проверены процентные изменения. Исходные массивы и геометрия в архив не включены, поэтому их байты не проверялись повторно при составлении этой сводки.
