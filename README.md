# Стенд сопоставления скана и эталонной сетки

Пакет для промежуточного просмотра.

## Состав

- `stand.py` - исходный скрипт загрузки, совмещения, расчёта отклонений, SOR и сравнения с результатом ИИ.
- `chek_model.py` - исходный скрипт применения предобученного Pointfilter. Сохранено фактическое имя файла; для запуска его нужно скопировать в папку Pointfilter.
- `filter_params.json` - сохранённый набор девяти настроек SOR: 10/20/30 соседей и std_ratio 1/2/3.
- `DATASETS.md` - перечень добавленных сеток и облаков, размеры геометрии и проверка сохранённого совмещения.
- Файлы STL и PLY - все предоставленные сетки и сканы, размещённые рядом со `stand.py`.
- `aligment.npz` и `scan_for_ai.npy` - сохранённое совмещение и готовый вход Pointfilter для пары `shoe`.
- `pointfilter_progress_report.pdf` - описание опыта, численные результаты, время и ограничения.
- `figures/cloud_overlay.png` - предоставленный скриншот наложения облаков.
- `letter.txt` - текст сопроводительного письма.

Оба Python-файла включены без изменений. Код Pointfilter и его веса в архив не включены; они доступны в репозитории авторов.

## Требуемые данные

В корне рабочей папки, рядом со `stand.py`, должны находиться:

| Файл | Назначение |
|---|---|
| `shoe.stl` | Эталонная треугольная сетка, включена в архив |
| `shoe_clean.ply` | Исходный скан, включён в архив |
| `filter_params.json` | Настройки SOR, приложены к архиву |
| `aligment.npz` | Сохранённые преобразования и центры для пары shoe, включён в архив |
| `scan_for_ai.npy` | Готовые совмещённые точки shoe для первого запуска ИИ, включён в архив |

Все 23 файла из предоставленного архива данных включены без изменения содержимого. Среди них 13 сеток STL, 8 облаков PLY и два файла состояния опыта. Совместимость `shoe_clean.ply`, `aligment.npz` и `scan_for_ai.npy` проверена: применение сохранённых преобразований с приведением результата к float32 точно воспроизводит сохранённый массив.

По умолчанию код обрабатывает пару `shoe`. Другие пары приложены для следующих экспериментов. Для них нужны собственные совмещения и отдельные результаты ИИ; файлы состояния `shoe` относятся только к этому опыту. Подробный перечень находится в `DATASETS.md`.

В этом опыте расстояния выражены в единицах координат эталона. Соответствие миллиметрам не установлено.

## Pointfilter

Репозиторий авторов: https://github.com/dongbo-z/Pointfilter

Для новой рабочей папки выполните из её корня:

```powershell
git clone https://github.com/dongbo-z/Pointfilter.git
Copy-Item .\chek_model.py .\Pointfilter\chek_model.py
```

Если репозиторий уже скачан, используйте имеющуюся папку и поместите туда `chek_model.py`.
Должен существовать файл `Pointfilter\Summary\pre_train_model\model_full_ae.pth`.

В рабочем опыте ИИ-окружение использовало Python 3.13.14, PyTorch 2.10.0+cu128 и NVIDIA GeForce RTX 3050 Laptop GPU с 4 ГБ видеопамяти. Вычисления модели выполняются на CUDA; автоматического переключения на CPU в скрипте нет.

## Порядок запуска

Все команды выполняются из корня рабочей папки, где находятся `stand.py`, `shoe.stl` и `shoe_clean.ply`. Это важно: пути к STL и PLY в скрипте относительные.
Окна Open3D блокируют выполнение: закройте каждое окно, чтобы перейти к следующему этапу.

### 1. Выполнить нейросетевую обработку готового входа

В архив уже включён `scan_for_ai.npy`, поэтому для приложенной пары `shoe` первым запускается ИИ-скрипт. Если сейчас активно другое окружение, сначала выполните `deactivate`.

```powershell
.\.venv-ai\Scripts\Activate.ps1
python .\Pointfilter\chek_model.py
```

Скрипт читает `scan_for_ai.npy` из родительской папки, загружает готовые веса, выполняет диагностику одной окрестности, затем обрабатывает весь скан. Результат сохраняется в `Pointfilter\scan_pointfilter.npy`.

Выполняется один проход модели. Для каждой точки используются радиус 0.05 диагонали габаритов скана, выборка 500 точек и пакет размера 1. После нормирования и PCA-выравнивания координаты предсказания возвращаются в систему совмещённого скана. При отсутствии подходящей окрестности исходная точка остаётся в результирующем массиве.

### 2. Сравнить результат с эталоном

```powershell
deactivate
.\.venv\Scripts\Activate.ps1
python .\stand.py
```

`stand.py` заново загрузит `shoe.stl` и `shoe_clean.ply`, применит приложенное совмещение, сохранит `scan_for_ai.npy`, рассчитает исходные расстояния и переберёт настройки SOR. Затем прочитает созданный на первом шаге результат ИИ, рассчитает расстояния до той же поверхности и покажет наложение: исходный скан окрашен картой отклонений, ИИ-результат - пурпурным. После фильтрации повторный ICP не применяется.

Именно порядок «ИИ, затем stand.py» предназначен для нового развёртывания приложенного готового опыта. Если запустить `stand.py` раньше, его последний блок попытается открыть ещё отсутствующий файл `Pointfilter\scan_pointfilter.npy`.

Для нового объекта без готовых `aligment.npz` и `scan_for_ai.npy` предварительно требуется ручное совмещение в `stand.py`. В таком случае исходная версия скрипта сначала создаст вход ИИ и затем остановится на отсутствующем ИИ-результате; после этого запускаются ИИ-скрипт и повторный проход `stand.py`. Автоматическое разделение стадий остаётся задачей следующей версии.

`deviations.csv` содержит исходные совмещённые координаты и расстояния до эталона. `filter_comparison.csv` содержит таблицу SOR. `summary.txt` в текущем коде сохраняет только время исходного расчёта расстояний и исходное среднее; медиана, максимум и показатели ИИ выводятся в консоль.

## Зафиксированный результат

- Исходный скан и ИИ-результат: 14 304 точки, пропусков ИИ-обработки нет.
- Исходные расстояния: среднее 0.0038454228; медиана 0.0031377566; максимум 0.027784238.
- После Pointfilter: среднее 0.0033927495; медиана 0.0028238497; максимум 0.02604205.
- Снижение: среднее 11.8%, медиана 10.0%, максимум 6.3%.
- SOR (20 соседей, std_ratio 2.0): осталось 13 665 точек, удалено 639; среднее 0.0036758061; медиана 0.0030564035; максимум 0.0224731080; время вызова около 0.0180 с.
- Цикл Pointfilter: 166.820 с, один запуск.
- Подготовка сцены и исходный расчёт расстояний: 0.104 с в приведённом контрольном запуске.

По коду подтверждено: таймер в `chek_model.py` охватывает полный цикл всех точек, включая подготовку окрестностей, передачи CPU/GPU, применение сети и восстановление координат. Он исключает загрузку модели, начальное построение индекса соседей, отдельную диагностику первой точки и запись файла. Текущая подпись таймера «Время расчёта отклонений» неточна: она обозначает время нейросетевой обработки.

Сравнение SOR и Pointfilter предварительное: SOR удаляет точки, а Pointfilter корректирует координаты с сохранением числа точек. Сближение с эталоном ещё не доказывает удаления именно шума или сохранения реальных дефектов. Проверена одна пара данных; по одному ракурсу невозможно строго оценить сохранность мелких деталей.

## Проверка перед упаковкой и замечания

Синтаксис обоих переданных скриптов проверен без запуска приложения. Архив содержит побайтово неизменённые исходники и данные. Дополнительно проверены структура STL/PLY, содержимое файлов состояния и точное совпадение совмещённых точек с результатом применения сохранённых преобразований. Численные расстояния и время взяты из предоставленных пользователем запусков; повторного запуска Open3D/CUDA при подготовке архива не было.

В диагностическом блоке `chek_model.py` перед основным циклом ошибка сейчас возникает сразу, если первая выбранная окрестность непригодна, даже когда следующие точки могли бы подойти. В приведённом опыте первая окрестность подходила и пропусков не было. Это отдельная небольшая правка для следующей версии, вместе с условным запуском ИИ-сравнения при первом старте.

Входные данные и сохранённое совмещение данного опыта включены в архив. Перед расширенным воспроизводимым экспериментом остаётся зафиксировать полные версии зависимостей и состояние репозитория Pointfilter. Виртуальные окружения, сам репозиторий Pointfilter и его веса в данный пакет не включены.
